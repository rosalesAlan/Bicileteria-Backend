PASOS RÁPIDOS PARA LEVANTAR EL SISTEMA
─────────────────────────────────────────────────────────────────

1. DETENER CONTENEDORES EXISTENTES

   docker-compose down -v

   Esto elimina:
   • Contenedores parados
   • Volúmenes de datos (limpia las BDs)
   • Redes creadas

2. RECONSTRUIR IMAGEN DEL BACKEND

   docker-compose build --no-cache backend

   El --no-cache fuerza a usar el Dockerfile actualizado

3. LEVANTAR SISTEMA COMPLETO

   docker-compose up -d

   -d = modo detached (corre en background)

4. ESPERAR A QUE INICIE

   Start-Sleep -Seconds 45

   Aproximadamente 45 segundos para que todos los servicios estén listos

5. VERIFICAR ESTADO

   docker-compose ps

   Todos deben mostrar: "Up X seconds (healthy)"

6. PROBAR ENDPOINT

   Invoke-WebRequest http://localhost:5147/api/Health/connections

   Debe retornar status 200 con:
   • postgresql.connected: true
   • mongodb.connected: true

¿QUÉ CAMBIÓ TÉCNICAMENTE?
─────────────────────────────────────────────────────────────────

ANTES (❌):
  docker-compose.yml:
  MongoDb__ConnectionString: "..."
	   ↓
  ASP.NET mapea a: MongoDb:ConnectionString
	   ↓
  Program.cs busca con GetConnectionString("MongoDb")
  que espera: ConnectionStrings:MongoDb
	   ↓
  NO COINCIDE ❌

DESPUÉS (✅):
  docker-compose.yml:
  ConnectionStrings__MongoDb: "..."
	   ↓
  ASP.NET mapea a: ConnectionStrings:MongoDb
	   ↓
  Program.cs busca con GetConnectionString("MongoDb")
  que espera: ConnectionStrings:MongoDb
	   ↓
  COINCIDE PERFECTO ✅

La precedencia en ASP.NET Core (de mayor a menor):
1. Variables de entorno (docker-compose.yml) ← AQUÍ estaba el problema
2. appsettings.{Environment}.json
3. appsettings.json
4. Fallback en código

Ahora la variable de entorno sobrescribe correctamente appsettings.json

─────────────────────────────────────────────────────────────────
LECCIONES APRENDIDAS
─────────────────────────────────────────────────────────────────

1. PRECEDENCIA DE CONFIGURACIÓN ES CRÍTICA
   Variables de entorno NO sobreescriben mágicamente
   Deben estar nombradas correctamente

2. MAPEO DE VARIABLES DE ENTORNO
   EN DOCKER: SECTION__PROPERTY (doble guión bajo)
   EN CÓDIGO: Section:Property (colon)
   EJEMPLO: ConnectionStrings__MongoDb → ConnectionStrings:MongoDb

3. MÉTODOS DIFERENTES DE ACCESO A CONFIGURACIÓN
   GetConnectionString("X") → busca en ConnectionStrings:X
   config["Section:Property"] → busca en Section:Property
   NO son iguales, requieren alineación

4. RED DOCKER ES AGNÓSTICA A LOCALHOST
   localhost dentro de un contenedor = el contenedor mismo
   Para comunicarte entre servicios = nombres de servicio (DNS)
   "mongodb" en docker-compose = resuelve a IP del contenedor MongoDB

5. HEALTHCHECKS DEBEN SER VÁLIDOS
   Un healthcheck a un endpoint inexistente engaña al orquestador
   El servicio puede estar "healthy" pero sin funcionar realmente
