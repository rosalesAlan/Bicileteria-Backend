## 📥 Instalación

### 1. Clonar el repositorio

```bash
git clone https://github.com/rosalesAlan/Bicileteria-Backend.git
cd Bicileteria-Backend
```

### 2. Restaurar paquetes NuGet

```bash
dotnet restore
```

### 3. Verificar la base de datos PostgreSQL

Asegúrate de que PostgreSQL esté corriendo:

```bash
# En Windows
# Abre Services y busca PostgreSQL, verifica que está iniciado
```

Si la base de datos **BicicleteriaDB** no existe, créala:

```sql
CREATE DATABASE "BicicleteriaDB";
```

### 4. Aplicar migraciones

```bash
dotnet ef database update
```

Esto creará las tablas `usuarios`, `productos` e insertará los datos semilla.

## ⚙️ Configuración

### appsettings.json

El archivo de configuración principal se encuentra en `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Port=5432;Database=BicicleteriaDB;User Id=postgres;Password=plokij"
  },
  "Jwt": {
    "Key": "tu_clave_secreta_super_larga_para_jwt_debe_ser_larga_minimo_32_caracteres",
    "Issuer": "https://bicicleteria.localhost",
    "Audience": "bicicleteria-app",
    "ExpireMinutes": 60
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.EntityFrameworkCore": "Information"
    }
  },
  "AllowedHosts": "*"
}
```

**Configuraciones importantes:**

| Clave | Descripción |
|-------|-------------|
| `ConnectionStrings.DefaultConnection` | Cadena de conexión a PostgreSQL |
| `Jwt.Key` | Clave secreta para firmar tokens JWT (⚠️ cambiar en producción) |
| `Jwt.ExpireMinutes` | Tiempo de expiración de tokens en minutos |

## 🗄️ Base de Datos

### Tabla: `usuarios`

```sql
CREATE TABLE usuarios (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    nombre VARCHAR(100) NOT NULL,
    apellido VARCHAR(100) NOT NULL,
    numerotelefono VARCHAR(20),
    mail VARCHAR(200) NOT NULL UNIQUE,
    tipo VARCHAR(50) NOT NULL,          -- 'admin', 'vendedor', 'cliente'
    passwordhash VARCHAR(500) NOT NULL
);
```

### Tabla: `productos`

```sql
CREATE TABLE productos (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    nombre VARCHAR(200) NOT NULL,
    descripcion VARCHAR(1000),
    precio NUMERIC(10,2) NOT NULL CHECK (precio >= 0),
    disponibilidad INTEGER NOT NULL DEFAULT 0  -- Stock disponible
);
```

## 🔌 API Endpoints

### Autenticación

#### **POST** `/api/auth/login`

Inicia sesión con email y contraseña.

**Request:**
```json
{
  "mail": "admin@bicileteria.com",
  "password": "Demo1234"
}
```

**Response (200 OK):**
```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "nombre": "Admin",
    "apellido": "Sistema",
    "mail": "admin@bicileteria.com",
    "tipo": "admin"
  }
}
```

**Response (401 Unauthorized):**
```json
{
  "message": "Credenciales inválidas"
}
```

## 🔐 Autenticación

### Sistema de Tokens JWT

El backend utiliza **JSON Web Tokens (JWT)** para autenticación:

1. El cliente envía `mail` y `password` al endpoint `/api/auth/login`
2. El servidor valida las credenciales contra la base de datos
3. Si son válidas, genera un JWT con:
   - ID del usuario
   - Email del usuario
   - Nombre completo
   - Tipo de usuario (role)
4. El cliente incluye el token en el header `Authorization: Bearer <token>` para futuras requests

### Configuración JWT

```csharp
// En Program.cs
builder.Services.AddAuthentication(options =>
{
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options =>
{
    options.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuer = true,
        ValidIssuer = jwtIssuer,
        ValidateAudience = true,
        ValidAudience = jwtAudience,
        ValidateLifetime = true,
        ValidateIssuerSigningKey = true,
        IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey))
    };
});
```

## 📝 Notas Importantes

### Seguridad

- ⚠️ **Nunca** commitear `appsettings.json` con credenciales reales en git
- 🔑 Cambiar la clave JWT (`Jwt:Key`) antes de pasar a producción
- 🔐 Las contraseñas siempre se hashean con BCrypt, nunca se almacenan en texto plano
- 🚫 CORS está configurado para permitir cualquier origen (solo para desarrollo)

### Desarrollo

- Las migraciones deben ejecutarse antes de iniciar la aplicación
- Si modificas modelos, genera una nueva migración: `dotnet ef migrations add MigracionNombre`
- Los logs de Entity Framework están habilitados para debugging

### Producción

- Cambiar `AllowedHosts` en `appsettings.json`
- Configurar CORS más restrictivo
- Usar variables de entorno para credenciales
- Implementar HTTPS obligatorio
- Configurar certificados SSL

## 🐛 Troubleshooting

### Error: "Authentication failed for user postgres"

**Solución:** Verifica que la contraseña en `appsettings.json` sea correcta.

### Error: "database does not exist"

**Solución:** Crea la base de datos manualmente:
```sql
CREATE DATABASE "BicicleteriaDB";
```

### Error: "Connection refused"

**Solución:** Verifica que PostgreSQL esté corriendo y que los parámetros de conexión sean correctos.

### Error: "Npgsql.PostgresException: password authentication failed"

**Solución:** Verifica el usuario y contraseña de PostgreSQL. Asegúrate de usar `User Id=` en lugar de `Username=`.
